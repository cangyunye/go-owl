# v1.10.0 变更记录

本版本包含 **13 个提交**，是一次**安全审计修复版本**：对 v1.9.1 全量代码评审（功能-文档对齐、功能-测试对齐、冗余、安全四个角度）后，修复黑名单匹配层的六类系统性绕过、两条绕过全部安全机制的执行路径、数据库文件权限等高危问题；顺带完成引擎收敛（V1 删除）、测试基建（CI 门禁 + 五场景 E2E 自动化）与文档修正。

## 🔒 安全修复

### 黑名单匹配层系统性绕过（高危，4690d07）
- **根因**：匹配前先把引号内容整体剥离再做子串匹配，而命令原样交给远端 shell 执行——`bash -c "rm -rf /"` 剥离后只剩 `bash -c ` 直接放行；同理 `$()`/反引号不在分隔符集、`base64 -d | sh`/`curl | bash` 纯文本匹配不可见、两条正则规则（`service .* stop`、`chown .*:[0-9]+`）按字面 Contains 永不命中、大小写敏感、行首 `sudo`/`su` 因规则带前导空格永不触发确认。
- **修复**（保留 `echo 'rm -rf /'` 防误报语义，原有 17 个黑名单测试全部原样通过）：
  - `bash/sh/zsh/dash/ksh -c` 与 `eval` 列入 root 确认规则
  - 分隔符集补 `(`、`` ` ``、`$`（命令替换点视为命令边界）
  - 管道中裸 shell 解释器按全局规则要求确认
  - `sudo`/`su` 规则去前导空格，行首提权同样触发确认
  - 匹配统一大小写归一；规则预编译——合法正则按 `(?i)` 正则匹配，非法语法回退字面匹配

### script 动作绕过全部安全机制（高危，c474aa6）
- **根因**：`script:` 动作由 ScriptExecutor 自行拨 SSH，不经过 `webCommandExecutor` 黑名单检查点，也不接 runCtx——剧本里写一段 `rm -rf` 脚本即可绕过「确认危险命令」交互，「取消运行」对 script 步骤无效。
- **修复**：引擎新增可选 `ScriptCheckFunc` 注入（CLI 未注入时行为不变），脚本内容（文件与 inline）先检查后执行；`NativeNodeExecutor` 新增 `ExecuteContext`（取消/超时即断连）；`ScriptExecutionOptions` 支持 ctx。顺带修复：`script+inline` 此前因文件存在性检查顺序错误从未可用。

### AI 触发路径走废弃 V1 引擎（高危，3098328）
- **根因**：AI 执行剧本仍调 V1（`context.Background()`），watchdog 失效——AI 触发的交互式命令永久挂死、取消只改库拦不住、无逐步进度。
- **修复**：AI 切到 V2 引擎（同步执行，结果读取语义不变），V1 全部删除。兼容性：V1 独有的 ansible 单键风格任务（`- 任务名: {command: ...}`）由解析器在 yaml.Node 层归一承接，存量剧本不受影响。

### owl.db 文件权限过宽（中危，6b3f107）
- **根因**：库目录 0755、文件按 umask 默认 0644，而库内有节点凭据（未设 `OWL_ENC_KEY` 时明文）与 `jwt_secret`——多用户机器上任意本地用户可读全部凭据并可伪造 JWT。
- **修复**：目录 0700；库文件及 WAL/SHM/journal 收紧 0600（serve 与 CLI 两条创建路径都生效）。

### 其他安全项
- **RunCancel 竞态**（S13）：取消走 Get→UpdateStatus 两步，引擎在两步间完成时终态会被改写为 cancelled——新增 `CancelIfActive` 单条条件 UPDATE，按受影响行数响应。
- **告警绑定强制放行可配置**（S12）：此前告警绑定触发的剧本无条件 `danger_confirmed=true`（operator 编写的剧本 + admin 配置的绑定 + 无黑名单执行）。现经设置键 `monitor.playbook_force_danger_confirmed` 控制，默认 true 保持历史行为，关闭后命中黑名单的剧本被正常拦截。
- **节点解析失败静默降级**（S15）：黑名单检查前 `getNodeInfo` 失败时 user 被置空、root 规则组整体失效。改为 fail-closed：解析失败即拦截（exit -1 + 可见错误），命令与 script 两条路径同一语义。

## ⚙️ 行为改进

- **失败判定统一**（f0985dd）：终态判定（`ExitCode!=0 && Error!=nil`）与 `FailureCount`（`ExitCode!=0`）两套口径并存是 946542b 类「误判成功」的温床——统一为 `IsFailedResult` 单一谓词（非零退出码即失败）。
- **输出截断 rune 安全**（f0985dd）：步骤输出 `[:4093]` 字节硬切可能切碎 UTF-8（乱码入库/广播），收敛为 `truncateRunes`（rune 边界回退）。
- **超时默认值收敛**（f0985dd）：10s/5min/30s 此前硬编码八九处，收敛为 `DefaultConnectTimeout`/`DefaultCommandTimeout` 常量。
- **预检警告落库**（af20e8f）：`run.Warnings` 此前只写内存，刷新后消失——`playbook_runs` 新增 warnings 列，Run 与告警触发两条路径落库、Get/List 读回。
- **黑名单用户缓存**（af20e8f）：按 run 缓存节点连接用户，多节点多步骤不再每步查库+解密凭据。
- **步骤状态判定去重**（af20e8f）：收敛为 `stepStatusOf` 单一函数。
- **文档修正**（588b2c8）：`--vars`→`--extra-vars`、SETTINGS 5 个不存在的配置键、template 子命令层级等误导性错误修正；serve-user.md 路由/API/设置三张表补全；新增 EXEC.md「危险命令黑名单」用户文档（拦截语义、`~/.owl/blacklist.yaml` 自定义、放行方式）。

## ✅ 测试基建

- **CI 测试门禁**（153bea3）：新增 `.github/workflows/ci.yml`，三个 go module（根 / serve 子模块 / owl-serve 子模块）push/PR 均跑 `go test`，根模块另跑 `go vet`。此前 release.yml 只构建发布、零测试门禁。
- **默认单测范围修正**（56aec26）：`cmd/plugins/serve` 是嵌套 go module，根目录 `go test ./...` 与 `./cmd/plugins/...` 均匹配不到它——handler 层 437 个测试函数此前不在任何默认测试范围；test-unit/test-quick/test-coverage 已纳入。
- **五场景 E2E 自动化**（228da4c）：`tests/e2e/test_sshd` 此前只是手动工具，发布说明的「五场景全 PASS」不可复跑——新增进程内真实执行 SSH server（exec 经 `/bin/sh -c` 真实执行、回传真实输出与退出码），走真实 sshExecutor → V2 全链路固化：命令成功、非零退出码透传、黑名单拦截（零 SSH 发起）、任务级超时断连、运行中取消。
- **死代码清理**：`toWebStepResults`（无调用方）、`Executor.Stop()` 占位（恒返回 not implemented 且无调用方，取消实际走 runCancels + ctx）、query_nodes 零断言测试补上真实断言。
- 本版本新增约 40 个测试；红测试先行（TDD）覆盖每个安全修复。

## 📋 升级注意事项

1. **黑名单拦截面扩大（有意为之）**：解释器调用、命令替换、管道接裸 shell、行首 sudo/su 现在会被要求确认。确属误报可在 `~/.owl/blacklist.yaml` 自定义规则（见 `docs/user/EXEC.md` 第 10 章）。
2. **剧本 `script:` 动作开始受黑名单约束**：含危险内容的脚本（含 inline 与文件）将被拦截或要求确认；这也修复了 `script+inline` 此前必然报 "script file not found" 的存量缺陷。
3. **owl.db 权限收紧为 0700/0600**：如有多进程跨用户读写同一库文件的部署，请迁移到同一用户运行；强烈建议设置 `OWL_ENC_KEY` 启用凭据加密。
4. **新设置键** `monitor.playbook_force_danger_confirmed`（默认 `true` 保持旧行为）：安全要求较高的环境可设为 `false`，告警绑定触发的剧本将正常过黑名单。
5. V1 剧本引擎已删除：全部执行路径（Web/API/AI）统一走 V2 引擎；ansible 单键风格剧本全链路支持。
