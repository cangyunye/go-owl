# v1.9.1 变更记录

本版本包含 **5 个提交**，是 v1.9.0 的修复版本：集中修复剧本执行的四个可见性/可控性缺陷——运行中看不到执行过程、失败步骤与失败原因不可见、交互命令永久卡住无法超时/取消、危险命令被拦却无任何提示。

## 🐛 问题修复

### 运行中看不到执行过程（问题 1/3）
- **根因**：V1 引擎每步 `AppendResult`+广播，`db7af51` 切到 V2 引擎时悄悄丢失——整个剧本在一次阻塞的 `pbExecutor.Execute()` 里跑完，结束后才一次性写库并广播终态。运行中详情卡永远显示「running · 暂无步骤结果」。fail_continue 因要跑完全部步骤空窗期最长、最明显；pipeline 只是因失败快停「看起来」有过程。（75707c9）
- **修复**：
  - 执行器新增 `SetProgressFunc`：每个节点步骤完成（含失败）即回调
  - Web 引擎接上回调：逐步 `AppendResult` + `RecordCommandExecution` + WebSocket 广播（多节点并发回调串行化，防读改写丢结果），删除结束后的一次性批量写库
  - `playbook_runs` 新增 `total_steps` 列（幂等迁移），运行前下发「任务数×节点数」预估总步数；前端进度条分母改用 `total_steps`，运行中即可见百分比推进

### 失败步骤不可见、run 静默失败（问题 2）
- **根因**：pipeline 快停的 `break` 发生在结果写入之前，失败步骤自身的执行记录被丢弃，后续步骤缺席（非 skipped）；终态写库错误信息传空字符串，run 变 failed 却无任何解释；且 Web 链路把非零退出码转成 exitCode 后返回 `err=nil`，pipeline 对退出码失败「假装没失败」，与 CLI 语义分裂。（b4c756d）
- **修复**：pre/tasks/post 三处均先保留结果再处理错误；中止失败必须返回非 nil error；`webCommandExecutor` 非零退出码转为 error（对齐 CLI）；终态写入真实错误（中止原因或「N/M 个步骤执行失败」计数）。

### 交互命令永久卡住、无法超时/取消（问题 4）
- **根因**：Web 链路 `session.CombinedOutput()` 不响应 ctx（同文件 `ExecuteStream` 有 watchdog，`Execute` 没有），5 分钟命令超时形同虚设——sudo 密码、y/n 确认等交互命令永久阻塞，run 永远停在 running；「取消」只改库状态，引擎只在启动时检查一次，`Stop()` 未实现，没有任何机制能中断。（bd1e54d）
- **修复**：
  - `sshExecutor.Execute` 加 watchdog：ctx 超时/取消即断连，`CombinedOutput` 得以返回
  - 新增运行取消注册表：`RunCancel` 除改库外传播 ctx 取消；引擎创建 runCtx 并在收尾检查——取消的运行终态写 `cancelled` 而非 failed/running，错误信息「运行已被用户取消」
  - `webCommandExecutor` 持有 run 级 parentCtx，每步命令从中派生超时 ctx；库操作始终用后台 ctx，取消后终态仍可写入

### 危险命令被拦无提示、Web 无法确认放行（问题 4）
- **根因**：黑名单（root 下 `rm -rf`/`sudo`/`kill -9` 等）拦截逻辑早已存在，后端也支持 `danger_confirmed`，但运行弹窗没有确认入口、前端从不传该字段——Web 上必拦；被拦步骤若触发 pipeline 快停又叠加「失败不可见」，用户只看到 run 变 failed、零解释。（957f04f）
- **修复**：运行弹窗新增「确认危险命令」勾选框（提交携带 `danger_confirmed`）；`preflightPlaybook` 按 root 最严格视角逐步预检，命中黑名单的步骤在运行前给出警告（步骤名+命令+放行方式）；预检警告文案泛化。

### fail_continue 有失败步骤却标 completed（E2E 发现）
- **根因**：`runCommand` 出错路径不复制底层结果的退出码（保持 0），`FailureCount()`（数 `ExitCode!=0`）得 0 → run 误标 completed、前端显示全绿；旧测试 `TestExecutor_Execute_FailContinueRunsAll` 把该缺陷固化为期望 Completed。（946542b）
- **修复**：出错时保留底层结果的退出码与输出（含重试路径）；修正旧测试语义——fail_continue 吞掉的是「中止」（继续跑完全部），不是「失败判定」。

## ✅ 回归测试防线

本次每个行为修复均配套回归测试，防止改版再次悄悄丢失：

- `TestExecutePlaybookRunV2_BroadcastsPerStep`：运行中（终态未到）已完成步骤必须已广播——V1→V2 式退化会直接红
- `TestProgressFunc_CalledPerStepIncludingFailure`：进度回调覆盖每步（含失败步）
- `TestExecuteOnNode_NonZeroExit_IsError`：退出码≠0 必须返回 error
- `TestExecutePlaybookRunV2_FailedStepVisible`：失败步骤在 results 可见、run.Error 非空
- `TestPipeline_FailureKeepsFailedStepResult` / `TestFailContinue_RecordsFailedAndSubsequentSteps` / `TestPreAndPostTaskFailure_KeepsFailedStepResult`：各模式/阶段失败结果保留
- `TestSSHExecutor_Execute_ContextTimeoutTerminates`：进程内挂死 sshd，ctx 超时后 Execute 必须返回
- `TestExecutePlaybookRunV2_CancelTerminates`：卡死步骤不放行，取消必须终止且终态 cancelled
- `TestPreflightPlaybook_BlacklistWarning`：rm -rf 命中必须告警、安全剧本零告警

可测性铺垫：`hub` 与 `ssh` 抽象为小接口，测试注入 fake hub / fake SSH（可控退出码/延迟/挂死）。

## 🔬 验证

- 新增 `tests/e2e/test_sshd`：进程内最小 SSH 服务（真实 SSH 协议 + 真实执行命令），E2E 不再依赖外部机器
- E2E 五场景全 PASS：pipeline 失败（失败步骤+原因+run.error 可见、后续不执行）、fail_continue（全部步骤可见、run failed、失败计数）、危险命令（预检警告+拦截原因可见+确认后放行）、挂死取消（运行中步骤实时可见、取消 0 秒生效、终态 cancelled）、超时（3s 超时 3.1s 真实返回）
- 浏览器实测 UI：确认勾选框渲染、运行中详情实时显示「1/2 步 · 成功 1」、取消后状态 cancelled
