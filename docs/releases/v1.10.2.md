# v1.10.2 变更记录

本版本包含 **1 个提交**，是 v1.10.1 的修复版本：集中修复剧本运行交互的三个问题。

## 🐛 问题修复

### 勾选「确认危险命令」后弹窗不关闭、可反复提交任务
- **根因**（三层叠加）：
  1. v1.10.1 把黑名单预检警告与「引用文件缺失」警告放进同一 `warnings` 通道，而前端逻辑是"有警告就不关弹窗"——勾选确认只放行执行期拦截，预检警告依然阻断，弹窗永远关不上、可反复点击
  2. 更深一层：预检警告在**任务创建之后**才返回，所谓"阻断"只挡了弹窗，任务已经创建并开跑——白跑一次还可能被反复点击刷出一堆任务
  3. 执行按钮无防重复提交保护
- **修复**：
  - 警告分桶：`warnings`（文件缺失，需处理后执行）与 `danger_warnings`（黑名单命中）分离
  - 后端预检**前置**：未勾选确认且命中黑名单时直接 `422` 拒绝，**不创建任务**；前端 catch 展示拒绝原因
  - 勾选确认后正常创建任务并关闭弹窗；执行按钮请求期间禁用防连点
- **测试**：`TestRun_RejectsBlacklistedWithoutConfirmation`（未确认 422 零任务 / 确认 202 创建）；既有 `TestRun_PersistsPreflightWarnings` 适配新语义

### start.sh 守护脚本步骤永久 running
- **根因**：`nohup java ... &` 类脚本主命令立即退出（`$?` 为 0），但 Java 守护进程继承 stdout/stderr 管道且不退出——gossh 的 `CombinedOutput`/`Wait` 都等到**通道 EOF** 才返回，而 EOF 永远不会来，步骤永久 running。手动终端执行只等命令退出所以"成功"。（用户生产实测）
- **修复**：`sshExecutor.Execute` 改用「哨兵标记」方案——命令包一层子 shell，主命令退出后 `echo 随机哨兵+退出码`；客户端在输出流中读到哨兵立即返回（截掉标记），绝不等待守护进程关闭管道。连接中断等异常路径由 `Wait`/ctx watchdog 兜底。E2E 验证：`nohup sleep 300 & echo` 场景 0.5 秒完成、输出无标记泄漏、后续步骤正常。
- **测试**：`TestSSHExecutor_Execute_ReturnsAfterCommandExit_DaemonOutput`——daemon 式 sshd（exec 后发输出+exit-status 但不关通道）下，主命令退出必须立即返回

### 运行详情改为模态窗口
- 点「查看」不再在页面下方常驻展示（避免反复向下跳），改为弹出模态窗口展示分步结果；关闭支持 × / 点击遮罩；WS 推送仅在模态打开且为该 run 时刷新；`?run=` 深链接同样走模态。
- 顺带修复模态窄列下状态徽章文字竖排（nowrap + 列宽调整）。

## 🧪 E2E 基建

`tests/e2e/test_sshd` 的 exec 处理改为 Start+Process.Wait 语义（主命令退出即发 exit-status、通道保持到管道 EOF），与真实 OpenSSH 一致，使守护进程场景可被 E2E 覆盖。
